**Command Library**

This library documents the common commands used for running and interacting with the trading bot project.

**Run Directory:** All commands should be executed from the project root directory: `C:\Users\EXT-PC\tbot`

---


### Docker & System Management

These commands are for managing the Docker containers and the overall application lifecycle.

- **`docker-compose up --build`**
  - **Definition:** Builds (or rebuilds) the Docker images from the `Dockerfile` and then starts all services.
  - **Usage:** Only use this when you have changed a configuration file like `docker-compose.yml`, `Dockerfile`, or when adding a new dependency to `requirements.txt`.

- **`docker-compose up -d`**
  - **Definition:** Starts all services in detached mode (runs in the background). If containers already exist, it will recreate them to apply new code changes.
  - **Usage:** Use this after making changes to the Python source code (`.py` files). It will quickly restart the containers to apply your changes.

- **`docker-compose logs`**
  - **Definition:** Displays the logs from all running services.
  - **Usage:** Good for seeing a snapshot of recent activity.

- **`docker-compose logs -f bot`**
  - **Definition:** Shows the live, streaming logs specifically for the `bot` service.
  - **Usage:** Useful for watching the real-time output of the bot after it has been started with `docker-compose up -d`.

- **`docker-compose exec bot <command>`**
  - **Definition:** Executes a single command inside the already running `bot` container.
  - **Usage:** This is the primary way we interact with the bot's command-line interface (CLI).

- **`docker-compose exec bot bash`**
  - **Definition:** Opens an interactive `bash` shell inside the `bot` container.
  - **Usage:** For advanced debugging or running multiple commands inside the container without repeatedly typing `docker-compose exec`.

- **`docker-compose down`**
  - **Definition:** Stops and removes all containers, networks, and volumes defined in the `docker-compose.yml` file.
  - **Usage:** Use this to completely clean up the environment. **Warning:** This will delete all data in your databases unless you have configured persistent volumes outside of Docker's default management.

### Host Machine Commands

These commands should be run on your host machine (your computer), not inside the Docker container.

- **`python historical_data_importer.py <symbol> <timeframe> <start_date> <end_date>`**
  - **Definition:** Connects to your MT5 terminal to download historical data and saves it as a CSV file for the bot to use in backtesting.
  - **Example:** `python historical_data_importer.py EURUSD D1 2023-01-01 2023-12-31`

- **`python mt5_bridge.py <symbol1> <symbol2> ...`**
  - **Definition:** Connects to your MT5 terminal and starts publishing a live data feed for one or more symbols to the RabbitMQ message queue.
  - **Example:** `python mt5_bridge.py EURUSD XAUUSD`

### Application CLI Commands

These are the specific commands available within the bot's application, run via `docker-compose exec bot python main.py <command>`.

- **`start-web`**
  - **Definition:** Starts the Flask web server and the Prometheus metrics endpoint.

- **`status`**
  - **Definition:** Checks and displays the connection status of the required services (RabbitMQ, InfluxDB, PostgreSQL).

- **`market-order <symbol> <volume> <requested_price> <sl> <tp> <slippage> <max_spread>`**
  - **Definition:** Places a simulated market order with slippage and spread control.

- **`limit-order <symbol> <volume> <price> <sl> <tp>`**
  - **Definition:** Places a simulated limit order.

- **`stop-order <symbol> <volume> <price> <sl> <tp>`**
  - **Definition:** Places a simulated stop order.

- **`twap-order <symbol> <total_volume> <duration_seconds> <num_chunks> <requested_price> <sl> <tp> <slippage> <max_spread>`**
  - **Definition:** Executes a Time-Weighted Average Price (TWAP) order.

- **`vwap-order <symbol> <total_volume> <duration_seconds> <num_chunks> <slippage> <max_spread>`**
  - **Definition:** Executes a Volume-Weighted Average Price (VWAP) order.

- **`partial-exit <position_id> <percentage_to_close> <current_price>`**
  - **Definition:** Manages a partial exit for an open position.

- **`trailing-stop <position_id> <current_price> <entry_price> <current_stop_loss> <trailing_step_points>`**
  - **Definition:** Manages a trailing stop-loss for an open position.

- **`time-based-exit <position_id> <reason>`**
  - **Definition:** Manages a time-based exit for an open position.

- **`calculate-signal-strength <symbol>`**

- **`detect-market-regime <symbol>`**
  - **Definition:** Detects the market regime for a given symbol.

- **`fetch-news <symbol> <start_date> <end_date>`**

- **`backtest <strategy> <symbol> <timeframe> <start_date> <end_date> [--secondary-symbol <symbol>]`**

- **`detect-patterns <symbol> <timeframe>`**
  - **Definition:** Detects candlestick patterns in historical data.

- **`discover-strategies <symbol> <timeframe> <start_date> <end_date> [--population] [--generations] ...`**
  - **Definition:** Runs the genetic algorithm to discover new trading strategies.

  - **Definition:** Retrains the machine learning model on new data.

- **`send-message <message> [--loop]`**
  - **Definition:** Sends a test message to the RabbitMQ queue.

- **`send-influx-data <measurement>`**
  - **Definition:** Sends continuous test data to InfluxDB.

- **`send-pg-data <table>`**
  - **Definition:** Sends continuous test records to PostgreSQL.

- **`crash`**
  - **Definition:** Intentionally crashes the bot to test the `restart: unless-stopped` policy.

This work also required adding a new feature to fetch the live account balance from MT5, as the bot was using a hardcoded value. This was implemented using a request/response pattern over RabbitMQ, where the bot requests the info and the `mt5_order_executor` provides it.

- **Automated Strategy Discovery:** (Implemented) Using techniques like genetic algorithms, the bot will actively seek to discover new, profitable trading strategies by. Promising discoveries will be promoted to its active strategy arsenal.
- **Machine Learning Model Retraining:** (Implemented) For ML-based strategies, the bot will automatically trigger and manage the retraining of its models with new data to prevent model drift.

- **Trade Confirmation:** Implemented a confirmation step for the `/trade` command using inline keyboards to prevent accidental orders. Fixed a bug in the callback data format that caused parsing errors (`too many values to unpack`).

  - **Ghost Position Cleanup:** Implemented logic in the executor to automatically mark trades as `closed` in the database if they cannot be found in the MT5 terminal.

### Telegram Web App Integration (telegram-webapp-roadmap)

This roadmap outlines the plan to integrate the existing Flask web UI as a Telegram Web App, making it accessible directly within the Telegram chat.

**Phase 1: Core Integration (In Progress)**
- **Expose the Web App:** The local Flask server (running on port 5000) must be made publicly accessible via a secure HTTPS URL. For local development, a tunneling service like `ngrok` is recommended (`ngrok http 5000`).
- **Add `/webapp` Command:** Implement a new `/webapp` command in `telegram_interface.py`.
- **Create Web App Button:** The `/webapp` command will send a message with a special inline button that contains a `web_app` field pointing to the public URL of the web interface.

**Phase 2: UI/UX Enhancements**
- **Include Telegram JS Script:** Add Telegram's official Web App JavaScript file (`telegram-web-app.js`) to the Flask app's base HTML template to enable communication between the web app and the Telegram client.
- **Dynamic Theme Matching:** Modify the web app's CSS to use Telegram's theme variables (e.g., `var(--tg-theme-bg-color)`) so the UI automatically matches the user's Telegram theme (light, dark, etc.).
- **Haptic Feedback:** Utilize the Web App API to provide haptic feedback (e.g., `Telegram.WebApp.HapticFeedback.notificationOccurred('success')`) for user actions to create a more native feel.

**Phase 3: Bi-directional Communication**
- **Send Data to Bot:** Implement a JavaScript function in the web app that uses `Telegram.WebApp.sendData()` to send information (e.g., text from an input field) from the web app back to the bot.
- **Receive Data in Bot:** Enhance the `telegram_interface.py` polling loop to check for and process `web_app_data` messages sent from the web app.
- **Close Web App Programmatically:** Add a "Close" button to the web app UI that calls `Telegram.WebApp.close()` to dismiss the web app window.
