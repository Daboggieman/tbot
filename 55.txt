**Command Library**

This library documents the common commands used for running and interacting with the trading bot project.

**Run Directory:** All commands should be executed from the project root directory: `C:\Users\EXT-PC\tbot`

### Docker & System Management

These commands are for managing the Docker containers and the overall application lifecycle.

- **`docker-compose up --build`**
  - **Definition:** Builds (or rebuilds) the Docker images from the `Dockerfile` and then starts all services.
  - **Usage:** Only use this when you have changed a configuration file like `docker-compose.yml`, `Dockerfile`, or when adding a new dependency to `requirements.txt`.

- **`docker-compose up -d`**
  - **Definition:** Starts all services in detached mode (runs in the background). If containers already exist, it will recreate them to apply new code changes.
  - **Usage:** Use this after making changes to the Python source code (`.py` files). It will quickly restart the containers to apply your changes.

- **`docker-compose logs`**
  - **Definition:** Displays the logs from all running services.
  - **Usage:** Good for seeing a snapshot of recent activity.

- **`docker-compose logs -f bot`**
  - **Definition:** Shows the live, streaming logs specifically for the `bot` service.
  - **Usage:** Useful for watching the real-time output of the bot after it has been started with `docker-compose up -d`.

- **`docker-compose exec bot <command>`**
  - **Definition:** Executes a single command inside the already running `bot` container.
  - **Usage:** This is the primary way we interact with the bot's command-line interface (CLI).

- **`docker-compose exec bot bash`**
  - **Definition:** Opens an interactive `bash` shell inside the `bot` container.
  - **Usage:** For advanced debugging or running multiple commands inside the container without repeatedly typing `docker-compose exec`.

- **`docker-compose down`**
  - **Definition:** Stops and removes all containers, networks, and volumes defined in the `docker-compose.yml` file.
  - **Usage:** Use this to completely clean up the environment. **Warning:** This will delete all data in your databases unless you have configured persistent volumes outside of Docker's default management.

### Host Machine Commands

These commands should be run on your host machine (your computer), not inside the Docker container.

- **`python historical_data_importer.py <symbol> <timeframe> <start_date> <end_date>`**
  - **Definition:** Connects to your MT5 terminal to download historical data and saves it as a CSV file for the bot to use in backtesting.
  - **Example:** `python historical_data_importer.py EURUSD D1 2023-01-01 2023-12-31`

- **`python mt5_bridge.py <symbol1> <symbol2> ...`**
  - **Definition:** Connects to your MT5 terminal and starts publishing a live data feed for one or more symbols to the RabbitMQ message queue.
  - **Example:** `python mt5_bridge.py EURUSD XAUUSD`
